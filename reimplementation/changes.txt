--------------------------------------------------------------------------------
2026-05-06  utils.py:load_data
--------------------------------------------------------------------------------
  - Removed the hard-coded data directory '/content/drive/MyDrive/BCI'
    from the body of load_data(). The function now accepts an optional
    `data_dir` parameter; when omitted it reads the BCI_DATA_DIR
    environment variable, falling back to the original hard-coded path
    if neither is provided. Existing callers (normal_results.py line 14,
    EEGNetBYOL.py / ablation.py via subject_to_arrays) keep working
    unchanged because both the parameter and the env var have defaults.

  - Why: the bregydoc/bcidatasetIV2a download in driver.ipynb places the
    .npz files in $HOME_FOLDER/data, which is not the path utils.py was
    written against. Without this change every notebook run would need
    to either edit utils.py or symlink the directory.

  - How to consume from the notebook:
      import os
      os.environ['BCI_DATA_DIR'] = DATA_DIR
      from utils import load_data
      subjectData, subjectDataEVAL = load_data()
    Or pass it explicitly:
      subjectData, subjectDataEVAL = load_data(data_dir=DATA_DIR)

--------------------------------------------------------------------------------
2026-05-07  normal_results.py:module-level setup + FBCSP_results
--------------------------------------------------------------------------------
  - Added `import os` at the top.

  - Replaced the module-level
        subjectData, subjectDataEVAL = load_data()
        DATA_DIR = '/content'
    with
        DATA_DIR = os.environ.get('BCI_DATA_DIR', '/content/drive/MyDrive/BCI')
        subjectData, subjectDataEVAL = load_data(data_dir=DATA_DIR)
    so DATA_DIR is now the *single* source of truth for both .npz and
    .mat paths, and load_data is called with an explicit argument
    instead of relying on the env-var fallback inside utils.

  - Inside FBCSP_results(), changed
        mat = loadmat(f'/content/A{idx:02d}E.mat')
    to
        mat = loadmat(f'{DATA_DIR}/A{idx:02d}E.mat')
    so the FBCSP true-label load uses the same DATA_DIR as everything
    else (was hard-coded to '/content', which was a bug — even before
    this reimplementation it disagreed with the module-level DATA_DIR).

  - Why: load_data() was succeeding (utils.py is path-flexible), but
    every downstream function failed with FileNotFoundError on
    /content/A01E.mat etc. because normal_results.py kept its own
    DATA_DIR='/content' hard-coded for the .mat files. With BCI_DATA_DIR
    set in the notebook, all three paths (.npz training, .npz eval,
    .mat labels) now resolve to the same data folder.

  - How to consume from the notebook: nothing changes for the user —
    just set os.environ['BCI_DATA_DIR'] = DATA_DIR before importing
    normal_results. The module-level lookup picks it up automatically.
